YouTube Recorder

Privacy policy

Effective date: 25 October 2026.

This policy describes the personal YouTube Recorder project maintained at its GitHub repository. It is a user-operated recording and file-upload tool, not a central cloud storage service.

Information used

The app processes the channel identifiers and stream URLs selected by the user, video/audio data being recorded, file names, timestamps, media metadata, checksums and upload receipts. To access Google Drive, rclone uses the OAuth authorization granted by the user, including the access and refresh tokens needed to maintain that authorization. Separate YouTube cookies may be supplied by the user for authorized source access.

Google Drive access and use

The recommended Google scope is https://www.googleapis.com/auth/drive.file. It permits the app to create and manage files created by, opened with or otherwise authorized for the app. The tool uploads recordings, verifies uploaded byte sizes and checksums, reads back its small connection-test files, and removes its temporary connection-test files. The user can select different permissions in their own rclone configuration; these are displayed during Google consent.

Google user data is used to provide the recording storage and verification features requested by the user. The project does not use Google user data for advertising, sale, unrelated profiling or training AI models. Use and transfer of information received from Google APIs will adhere to the Google API Services User Data Policy, including the Limited Use requirements.

Storage and security

Authorization credentials are kept in the user's private local configuration or the secret store of the hosting service they configure. Runtime configuration files are temporary and restricted to their owner where the operating system supports it. Credential values are not intentionally included in source code or diagnostic reports. The project maintainer does not operate a separate central database of users' Google tokens or recordings.

Recordings and receipts remain in the user's chosen local directories and storage services until the user deletes them. Temporary credentials and generated connection-test files are cleaned up by their respective test or upload processes. A machine or provider outage may prevent normal cleanup. Hosting providers may retain their own operational logs under their policies.

Sharing and optional providers

Drive uploads do not intentionally create public sharing permissions. If the user enables Gofile or GitHub Release fallback, recording data and file metadata can be sent to those providers. Such backups may be public, especially in a public repository or through a public download link. If Telegram notifications are configured, the selected chat receives recording status and access links, not Google refresh tokens or YouTube cookie files. Provider access and privacy policies apply in addition to this policy.

User control and deletion

The user can revoke the app's Google access on the Google third-party connections page, remove its configuration from their computer or hosting secret store, and delete recordings from their chosen storage services. Revoking authorization does not automatically remove recordings already uploaded. The user remains responsible for deleting those copies.

Contact and changes

Questions can be submitted through the project issue tracker. Do not include private account data or credentials. Material changes to the app's data practices will be reflected in this policy.
